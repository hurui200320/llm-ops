### Qwen3.8 `STRATA_SET` keys vs `dsv41` speed surface

`STRATA_SET` maps lowercase keys to `--flag` (unknown flags exit 2 in `src/dsv41/ds4_main.cpp`) and `ALL_CAPS` to env:

| Knob / Qwen key | Default / `dsv41` behavior |
| --- | --- |
| `kv=fp16`, `pipeline-windows`, `trim-stage-weights`, `spec-min-p`, `prompt-cache-spread` | No such flags on `dsv41` (own MLA cache ~17 MB / 6.5K tok; DSpark replaces spec decoding) → exit 2 |
| `resident-budget-gib=N` → **`ssd-cache=GB`** | Auto (`avail-12`, cap 48); RAM store for CPU-lane experts (lane pins `36`; never pass `0`). `ssd-policy=lru\|lfu\|lfulru` (default `lru`), `DS4_STORE_THREADS=8` |
| `vram-reserve-mib` / `later-mib` → **`reserve-mib=N`** | Default `600`; single per-GPU VRAM subtraction when sizing expert cache at load (`vram-experts=1.0`) |
| `conversation-cache-*` → **`STRATA_DS4_SLOT_*` (env)** | Auto parking: `SLOT_KEEP` (on), `SLOT_GB` (2), `SLOT_CAP` (4 in RAM), `SLOT_MIN` (1024 tok), `SLOT_DAYS` (7) |
| **`prefill-chunk=N`** | Default `8192` (`kVlRows`); `16384` halves expert re-reads per prompt but takes ~1.9 GB VRAM from expert cache |
| **`threads=1\|off`**, **`cpu-threads=N`** | Host thread per GPU enqueuing layers (default `off`); CPU-lane threads (default physical cores = `16`) |
| **`dspark=1\|off\|none\|auto`**, **`dspark-conf=0.65`** | Drafter (`auto` leaves it unloaded here; `off` still loads it!). `STRATA_DS4_DSPARK_CUM=F` (off) |
| `layer-split=N` → **`DS4_SPLIT=a,b` (env)** | `--layer-split` is ignored; `DS4_SPLIT` overrides auto trunk split. `STRATA_SCORES_THREAD` / `STRATA_HIPBLASLT_TABLE` are inert |

**`reserve-mib` is not a runtime free-VRAM floor**: at default `600`, load logs 586/592 MiB free, but mid-prefill
chunk buffers drop free VRAM to **61 MiB on `card1` (monitor, x16) and 262 MiB on `card0` (x4)** (`min free ~= reserve
- 530 MiB` on monitor, `reserve - 330 MiB` on other). Setting `reserve-mib=896` holds 352–357 / 544–552 MiB free
during prefill (meeting the 300–400 MiB monitor target).

### Prefill mechanics (`src/dsv41`) and ceiling reference

- **Single-device-only layer-major cache**: `lm_begin()` returns false when `devs.size() != 1`, so multi-GPU prompts
  stream chunk by chunk without `DS4_LAYER_CACHE_MB`, making pp flat across context.
- **GPU-compute bound (72% compute, 28% read wait, ~0% CPU lane)**: At 105k/220k tokens each card streams 203/431 GB at
  0.69–0.70 GB/s and waits 28% of prefill time for reads; the CPU lane runs `0.0-0.2%` of prefill experts (all stream to
  GPU). `--cpu-threads` and AVX-VNNI (`222 us` vs AVX2 `254 us`) affect decode only.
- **Kept set**: `STRATA_SET="ssd-cache=36 reserve-mib=896"`, auto `[0,20]`/`[21,39]`+head split, `--prefill-chunk 8192`,
  `--dspark auto` (unloaded). (For reference, upstream #4042 on 2× RTX PRO 6000 192 GB VRAM with all 15,360 experts
  resident reached 2,405–2,457 pp / 98–116 tg; #3933 on R9700 + XTX reached 166 pp.)

## Card identity and `--reserve-mib` runtime floor

HIP orders GPUs by PCI bus while sysfs does not, so `CUDA0` and `card0` are opposite cards:

| Role | PCI | sysfs | HIP (`maya.py --gpu 0,1`) | H2D link & prompt ring | Desktop idle | Runtime floor target |
| --- | --- | --- | --- | --- | --- | --- |
| Monitor | `0000:03:00.0` | `card1` | **CUDA0** | 27.4 GB/s (394 MB, 44 slots) | ~407–460 MiB | **≥ 500 MiB** |
| Other (PCH x4) | `0000:09:00.0` | `card0` | **CUDA1** | 7.1 GB/s (39 MB, 4 slots) | ~27 MiB | **≥ 300 MiB** |

At `--reserve-mib 1024` (baseline A0: 4,194 VRAM experts, 8K resident chunk), load logs ~1,010 MiB free, but the
desktop (~407 MiB on CUDA0) + first-request buffers (~212 MiB/card) + long-prompt slabs (~110 MiB/card) drop runtime
free VRAM to **18 MiB on CUDA0 and 386 MiB on CUDA1** (`min free CUDA0 ~= reserve - 1005 MiB`, `CUDA1 ~= reserve - 638
MiB`). With the **borrowed 16K chunk** (`DS4_CHUNK_GFX11=16384`, below), chunk row buffers overlay expert slots between
prompts instead of sitting resident, cutting per-card runtime overhead to **~648 MiB** (`min free ~= reserve - 648 MiB
- desktop`; `--reserve-mib 1664` gives **592 / 1,013 MiB** min free).

# 20261105 `DS4_SPLIT=18,22`: the auto layer split was costing ~40% pp

## Why the auto planner picks the wrong split on this pair

`DS4_SPLIT` sets per-group trunk layer counts (`ds4_model.cu:4042`). When unset, the auto planner
(`ds4_model.cu:3990-4040`) minimizes streamed expert bytes `max(0, experts(a..b) - (cap[gi] - dense))` using `cap[gi] =
min_member(free0 - reserve - 400 MB - 1.1 GB)`. It has **no link-speed term** and takes `free0` from HIP, which reports
the monitor card's ~460 MiB desktop VRAM as free. Auto therefore gives CUDA0 (monitor) 21 of 40 layers when it actually
has ~460 MiB less room, pushing it over a resident/streamed cliff. Moving layers from CUDA0 to CUDA1 shrinks CUDA0
weights+caches (`2.87+0.48` → `2.49+0.29 GB` at `18,22`), freeing expert slots on CUDA0 (`2,335` → `2,445`).
