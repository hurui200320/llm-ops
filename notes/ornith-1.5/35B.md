## 20261001 Host-memory and checkpoint measurements

Preserve 256K context, one slot, F16 K/V caches, ubatch 512, GPU vision projector,
GPU split and speculative decoding disabled. KV-cache quantization is excluded.

On `b11096-c550d2f60`, a 224915-token synthetic Python-source fixture followed
by 17 appended review turns measured cold prefill at 1953.25 t/s. One-token
appended requests took approximately 0.44-0.46 s. A recent-history edit reused
225345 tokens, processed 93 and took 0.576 s; separate 128-token generation ran
at 30.65 t/s. These are serving/memory results, not coding-quality scores.

Partial recurrent-state checkpoints were **62.813 MiB each**, independent of
the long attention context, since no MTP draft was enabled. At the existing
32-checkpoint cap, maximum anonymous memory was only 4.52 GiB. Cgroup memory
peaked at 40.33 GiB, dominated by approximately 35.77 GiB of reclaimable model
file cache. About 60 MiB of container swap existed before inference and mostly
decreased during the run; this is not evidence of checkpoint saturation.

The first survey attempt assumed fixed model ports and stopped before inference.
llama-swap reassigned `${PORT}` on config reload; subsequent measurements discover
the published container port instead. The backend itself was still healthy.

On `b11312-0c1e57098`, retaining 32 checkpoints and an 8 GiB saved-prompt cache
under `--memory 32g --memory-swap 32g`:

| Model | Cold prefill | Median appended latency | Recent edit | 128-token decode |
| --- | ---: | ---: | ---: | ---: |
| Official Q8_0 | 1947.98 t/s | 0.438 s | 0.580 s | 30.76 t/s |
| Abliterated Q8_0 | 1954.94 t/s | 0.435 s | 0.601 s | 30.63 t/s |

Both used 224915-token synthetic initial prompts and 17 appended turns. Maximum
anonymous memory was about 4.60 GiB; checkpoints stayed 62.813 MiB each. The
hard cgroup limit reclaimed model-file cache, with zero container swap and no
OOM events. The official model's speed is essentially unchanged from baseline;
the abliterated variant was validated on the new build without a same-session
old-build speed comparison.

Both variants passed plain/streamed tool-call/result loops, strict JSON-schema
output, and synthetic red-image input. Keep the existing checkpoint and prompt
cache sizes; there is no demonstrated reason to cut their small recurrent-state
checkpoint budgets. The ROCm image is pinned and normal logging uses `-lv 3`.
Context, precision, sampling, ubatch, GPU split, vision and speculation are unchanged.

A separate official-model workspace-switch test at 63.2K tokens saved a
1926.474 MiB prompt state. Returning reused 63181 tokens, processed four and
took 0.430 s, compared with 16.38 s for the initial cold prefill. Keep the 8 GiB
saved-prompt cache: this test demonstrates useful reuse on slot replacement,
with no swap or OOM events.

Both variants passed all four checks again through llama-swap after final config
sync. Their actual 32-checkpoint/8 GiB cache settings, F16 defaults, 256K single
slots and 32 GiB/no-swap container limits were verified without swap or OOM.

## 20261002 Expert offload, concurrency and idle-cache tuning

Keep both GPU-only single-slot deployments: private 256Ki context, split
`20,22`, batch 2048 / ubatch 512, GPU vision, F16 KV and no speculation.
Baseline/cache-only controls passed at 228347 cold tokens (87.1%):

| Variant | Cold pp (t/s) | tg (t/s) | Cached median (s) | Peak VRAM (GiB) |
| --- | ---: | ---: | ---: | ---: |
| Official Q8_0 | 1841.08 | 30.98 | 0.439 | 22.343 / 21.423 |
| Abliterated Q8_0 | 1834.98 | 30.75 | 0.432 | 22.351 / 21.443 |

Disabling eager idle copies at one slot made no material speed/RAM difference;
anonymous RAM stayed ~4.1 GiB.

One CPU expert layer with `--no-op-offload` measured 1560.59 pp / 29.43 tg:
~15.2% / 5.0% slower than GPU-only, versus ~45.4% pp loss with default operation
offload. More early-layer offload mainly frees GPU 0 and requires rebalancing.

Optional capacity, official GGUF only: three CPU expert layers, split `21,21`,
`--no-op-offload --no-cache-idle-slots`, batch 2048 / ubatch 512, and
`--ctx-size 524288 --parallel 2 --no-kv-unified` (two private 256Ki slots).
At 256557 cold tokens/slot (97.87%), cached turns, edits, 1024-token decode and
vision passed: 1150.67 aggregate pp, 27.04 single-active tg, 18.89 / 18.92
concurrent tg, peak VRAM 22.565 / 22.349 GiB. Aggregate pp uses total tokens / wall time.

Without idle copies, cached median fell 2.810 → 0.758 s and anonymous RAM
11.815 → 5.525 GiB versus the shorter idle-copy run (not a same-length A/B).
Keep the 8 GiB saved-prompt cache. Concurrent decode misses the 25 t/s/request
target; mixed cold prefill reduced effective decode to 3.53 t/s.
Batch 2048 beat 512 for mixed throughput (4.14 vs 3.20 effective tg), but with
larger observed stream gaps (2.722 vs 0.981 s, not upper bounds).
Two slots do not provide latency isolation; smaller batches do not solve contention.

Single synthetic runs on digest-pinned `b11312-0c1e57098`, not general quality
benchmarks. VRAM: 100-ms peaks, GPU 0 (CPU x16) / GPU 1 (chipset x4). Container
swap/OOM stayed zero; host swap increased and heavy desktop load remains untested.

Macro:

```yaml
  # Host RAM 32 GiB with 32GB swap; VRAM is unaffected.
  # Target and draft KV caches deliberately retain their original F16 defaults.
  # Reuse ROCm compilation results across disposable containers. The named
  # volume is local to Docker; no model weights or conversation state go here.
  # Do not add prune_expiration: this COMGR build rejects it and disables caching.
  # Placement/context are explicit: skip auto-fit estimates, keep warmup enabled.
  # common start of docker run llama server
  "docker-server-rocm": >
    docker run --name ${MODEL_ID} --init --rm
      --memory 32g --memory-swap 64g
      -v llm-ops-comgr-cache:/root/.cache/comgr
      -e AMD_COMGR_CACHE=1
      -e AMD_COMGR_CACHE_DIR=/root/.cache/comgr
      -e AMD_COMGR_CACHE_POLICY=prune_interval=1h:cache_size=0%:cache_size_bytes=256m:cache_size_files=0
      --device /dev/dri
      --device /dev/kfd
      --group-add=video
      --group-add=render
      --security-opt label=disable
      --security-opt seccomp=unconfined
      -p ${PORT}:8080
      -v /mnt/unenc-xfs/models:/models:z
      -v /mnt/unenc-xfs/llm-ops/templates:/templates:z
      ghcr.io/ggml-org/llama.cpp:full-rocm
      --server
      --port 8080 --host 0.0.0.0
      --alias ${MODEL_ID}
      -lv 3
      --fit off


  # Ornith's recurrent checkpoints are small (~63 MiB), with no active draft.
  # Minimum spacing does not guarantee periodic checkpoints or context coverage;
  # message boundaries and prompt-end checkpoints can bypass it.
  "ornith15-ctx-ckpt": >
    --cache-ram 40960
    --ctx-checkpoints 32
    --checkpoint-min-step 8192
```
