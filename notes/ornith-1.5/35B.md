## 20261001 Host-memory and checkpoint measurements

Preserve 256K context, one slot, F16 K/V caches, ubatch 512, GPU vision projector,
GPU split and speculative decoding disabled. KV-cache quantization is excluded.

On `b11096-c550d2f60`, a 224915-token synthetic Python-source fixture followed
by 17 appended review turns measured cold prefill at 1953.25 t/s. One-token
appended requests took approximately 0.44–0.46 s. A recent-history edit reused
225345 tokens, processed 93 and took 0.576 s; separate 128-token generation ran
at 30.65 t/s. These are serving/memory results, not coding-quality scores.

Partial recurrent-state checkpoints were **62.813 MiB each**, independent of
the long attention context, since no MTP draft was enabled. At the existing
32-checkpoint cap, maximum anonymous memory was only 4.52 GiB. Cgroup memory
peaked at 40.33 GiB, dominated by approximately 35.77 GiB of reclaimable model
file cache. About 60 MiB of container swap existed before inference and mostly
decreased during the run; this is not evidence of checkpoint saturation.

The first survey attempt assumed fixed model ports and stopped before inference.
llama-swap reassigned `${PORT}` on config reload; subsequent measurements discover
the published container port instead. The backend itself was still healthy.

On `b11312-0c1e57098`, retaining 32 checkpoints and an 8 GiB saved-prompt cache
under `--memory 32g --memory-swap 32g`:

| Model | Cold prefill | Median appended latency | Recent edit | 128-token decode |
| --- | ---: | ---: | ---: | ---: |
| Official Q8_0 | 1947.98 t/s | 0.438 s | 0.580 s | 30.76 t/s |
| Abliterated Q8_0 | 1954.94 t/s | 0.435 s | 0.601 s | 30.63 t/s |

Both used 224915-token synthetic initial prompts and 17 appended turns. Maximum
anonymous memory was about 4.60 GiB; checkpoints stayed 62.813 MiB each. The
hard cgroup limit reclaimed model-file cache, with zero container swap and no
OOM events. The official model's speed is essentially unchanged from baseline;
the abliterated variant was validated on the new build without a same-session
old-build speed comparison.

Both variants passed plain/streamed tool-call/result loops, strict JSON-schema
output, and synthetic red-image input. Keep the existing checkpoint and prompt
cache sizes; there is no demonstrated reason to cut their small recurrent-state
checkpoint budgets. The ROCm image is pinned and normal logging uses `-lv 3`.
Context, precision, sampling, ubatch, GPU split, vision and speculation are unchanged.

A separate official-model workspace-switch test at 63.2K tokens saved a
1926.474 MiB prompt state. Returning reused 63181 tokens, processed four and
took 0.430 s, compared with 16.38 s for the initial cold prefill. Keep the 8 GiB
saved-prompt cache: this test demonstrates useful reuse on slot replacement,
with no swap or OOM events.

Both variants passed all four checks again through llama-swap after final config
sync. Their actual 32-checkpoint/8 GiB cache settings, F16 defaults, 256K single
slots and 32 GiB/no-swap container limits were verified without swap or OOM.
