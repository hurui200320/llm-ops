Tried Qwen3.8 27B, first, speed:

+ With MTP, ubatch 256:    total 1680 s, pp 619.92 t/s  tg 19.93 t/s  accept_rate 0.6075
+ With MTP, ubatch 128:    total 1865 s, pp 388.90 t/s  tg 19.96 t/s  accept_rate 0.6104
+ MTP, CPU mmproj, ub 480:               pp 535.54 t/s                                    (only ub changed, affecting pp, tg should be same)
+ No MTP, ubatch 512:      total 2095 s, pp 876.64 t/s  tg 14.25 t/s

Moving MTP to CPU is not worth the effort, not stable and at best it has no speed up, but most likely will slow down.
With ub 256, VRAM usage sets about 23.7/23.9GB, I'm not comfortable with this, system might crash/freeze if some UI start renders something.
But lower ub to 128 doesn't free much VRAM, but half the pp speed, not worth it.

Also, as usual, Qwen model can't stop thinking. Asking who is in the photo takes 9.5k token to reasoning,
while the final answer only takes like 500 token less.
The chat templates defaults to xhigh thinking and preserve history.

Preserving thinking history can be both good and bad. On good side, it **might** help maintain model's intelligence,
but the bad side is obvious: blow up context window very quick.

The default model should preserve the default behaviour. Preserving thinking is by default enabled in chat template,
which may suggest the qwen model is trained on this. However, to save context, thanks to llama-swap, we can add model alias
to inject request parameter to control this. So model with `xxx:ntp` will inject `preserve_thinking: false` in `chat_template_kwargs`.

> Actually, llama-swap don't merge objects, it will replace the whole `chat_template_kwargs` with ours.
> But usually you don't need that object. For thinking budget and other stuff, OpenAI API has standard fields for them.
> So this shouldn't harm anything.
