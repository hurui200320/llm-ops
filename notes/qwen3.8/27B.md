Preserving thinking history can be both good and bad. On good side, it **might** help maintain model's intelligence,
but the bad side is obvious: blow up context window very quick.

The default model should preserve the default behaviour. Preserving thinking is by default enabled in chat template,

to inject request parameter to control this. So model with `xxx:npt` will inject `preserve_thinking: false` in `chat_template_kwargs`.

# 20261001 Host-RAM and context-checkpoint tuning

Keep target and MTP draft K/V caches at the original F16 precision. KV-cache
quantization is deliberately excluded: coding and agentic-loop reliability take
priority over memory savings. Context remains 262144, parallel remains 1,
and MTP, CPU vision placement, ubatch 256 and the GPU split are unchanged.

Measured on fedora-tuf (i7-13700K, 64 GB RAM, dual 7900 XTX), initially using
`b11096-c550d2f60`. The workload is synthetic Python source, approximately 225K
prompt tokens, followed by short appended review turns. One-token responses
isolate cache/checkpoint overhead; a separate 256-token response measures decode.
These are serving/memory measurements, not a model-quality benchmark.

The original 32-checkpoint setup reached 29.53 GiB of cgroup host memory after
11 appended turns, with only 26 checkpoints retained. Each checkpoint was about
1035 MiB at this context length. The test was stopped before saturating the cap;
the container had begun using about 9.5 MiB of swap. Cold prefill was 692.12 t/s,
and median appended-turn latency was 2.09 s.

With 16 checkpoints, RAM-cache disabled for this comparison, and Docker
`--memory 32g --memory-swap 32g`, 18 appended turns completed without swap or
OOM events. Cgroup memory peaked at 28.08 GiB, including about 10.05 GiB of
reclaimable file cache; anonymous memory after the append sequence was 17.96 GiB.
Cold prefill was 690.83 t/s and median appended-turn latency was 2.15 s. Editing
a recent user message took 2.63 s, reusing 225407 tokens and processing only 93.
The separate 256-token decode ran at 21.37 t/s. Reducing the cap controls memory
without reducing the context window; old edits may require more re-prefill.

Checkpoints contain both the recurrent target state and the MTP draft's ordinary
attention state. The latter grows with context: roughly 150 MiB of recurrent
state plus 4 KiB per cached draft token. `--cache-ram` limits saved prompt states,
not active checkpoints. The original 8 GiB saved-prompt cache had already logged
a rejected 10.0 GiB conversation state, so increasing it would compete with the
checkpoint budget rather than fix long-context memory pressure.

# 20261002 MTP, placement and ubatch comparison

Keep MTP depth 2 / ubatch 256 / split `35,31` provisionally for both variants,
with one private 256Ki slot, F16 target/draft KV and CPU vision. Baseline headroom
is still tight (~334 MiB on GPU 1); no winning replacement was found.
Tested at 228385 cold tokens (87.1%), with cached turns, edits, decode and vision:

| Candidate | Cold pp (t/s) | tg (t/s) | Peak VRAM (GiB) |
| --- | ---: | ---: | ---: |
| Official baseline | 669.73 | 20.48 | 22.761 / 23.658 |
| Uncensored baseline | 668.62 | 21.83 | 22.761 / 23.654 |
| Official, no MTP (corrected) | 773.56 | 14.43 | 22.552 / 21.345 |
| Official, split `36,30` | 633.02 | 21.27 | 23.951 / 22.326 |
| Official, MTP depth 1 | 668.91 | 18.76 | 22.671 / 23.888 |
| Official, ubatch 128 + no idle copies | 365.09 | 21.33 | 22.861 / 23.437 |

- **No MTP:** cached median 2.172 → 0.816 s, anonymous RAM 16.783 → 4.862 GiB,
  but ~29.5% slower decode. A memory-saving fallback, not a universal win.
- **Reject split `36,30` and depth 1:** only ~34 / 98 MiB headroom respectively;
  depth 1 also slowed decode without reducing anonymous RAM.
- **Reject ubatch 128 + `--no-cache-idle-slots`:** nearly halves pp without
  fixing cached overhead or VRAM pressure; this combined trial cannot isolate the flags.
- **Replace `--spec-type` when disabling MTP:** repeated flags are additive;
  appending `none` left MTP active and invalidated the first control.

Alternative settings were tested only on the official GGUF, not the uncensored
variant. Single synthetic runs on digest-pinned `b11312-0c1e57098`, not quality or
real-corpus acceptance benchmarks. VRAM: 100-ms peaks, GPU 0 (CPU x16) / GPU 1
(chipset x4). Container swap/OOM stayed zero; host swap increased and heavy desktop
load remains untested.
